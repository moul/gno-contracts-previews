IPv4 addressing as integer arithmetic (ParseAddr, ParsePrefix, Prefix.Contains, Classify, Summarize).

An address is its 32-bit value and nothing else, so every operation is a shift or a mask: no allocation on the hot path, no string ever round-trips through a number to be compared, no float anywhere.

 1import "gno.land/p/moul/x/daily/ipaddr/v0"
 2
 3a, ok := ipaddr.ParseAddr("192.168.1.37")   // ok
 4_, ok = ipaddr.ParseAddr("010.0.0.1")       // false: leading zero
 5
 6p, _ := ipaddr.ParsePrefix("192.168.1.37/24")
 7p.String()        // "192.168.1.37/24", kept as written
 8p.Masked()        // 192.168.1.0/24
 9p.Contains(a)     // true
10p.Last()          // 192.168.1.255
11p.Usable()        // 254
12
13b, special := ipaddr.Classify(a)             // private-use, RFC 1918
14ipaddr.Summarize(lo, hi)                     // a range, as CIDR blocks

The parser is strict in the one place it matters. A leading zero in an octet is rejected rather than read as octal: 010.0.0.1 is 10.0.0.1 to a browser and 8.0.0.1 to inet_aton, so a parser that accepts it has to pick a reading, and whichever it picks disagrees with something else in the stack. None of the C shorthands are accepted either, so there is no second spelling of an address to argue about.

A prefix keeps the address it was written with, as Go's net/netip does, so 192.168.1.37/24 renders back as itself. Everything that asks about the block it names masks first: Contains, First, Last and Count all answer for 192.168.1.0/24. Masked is the canonical spelling, IsMasked asks whether you already have it.

Summarize(first, last) is the piece CIDR notation cannot express directly: an arbitrary range almost never is a prefix, and 10.0.0.5 through 10.0.0.20 takes five blocks. Each one is the widest block that can start at the cursor, narrowed until it also ends inside the range. Both steps are load-bearing: dropping the second returns four blocks for that range, one of which runs past 10.0.0.20.

Three small things the 32-bit arithmetic gets right and a hand-rolled version usually does not. Count returns uint64, because 0.0.0.0/0 holds 4294967296 addresses and a uint32 cannot count them. Next and Prev return a bool rather than wrapping, so a walk to 255.255.255.255 terminates. Usable is the full count for a /31 and a /32 rather than count minus two, since a /31 is a point-to-point link whose two addresses are both hosts (RFC 3021).

SpecialBlocks is the IANA IPv4 special-purpose registry, sixteen entries with the RFC that defines each. Classify returns the most specific match, which is why 255.255.255.255 comes back as the limited broadcast address rather than as 240.0.0.0/4.

IPv6 is deliberately out. It is 128 bits, has no broadcast address and carries a zone identifier, and folding the two into one type is what makes a library like this hard to read.

Overview

Package ipaddr is IPv4 addressing as integer arithmetic: a strict parser, a CIDR prefix with the questions people actually ask of one, the IANA special-purpose registry, and the range-to-CIDR summarizer.

An Addr is the address's 32-bit numeric value and nothing else, so every operation here is a shift or a mask. There is no allocation on the hot path, no string ever round-trips through a number to be compared, and no float is involved anywhere.

Three things are worth knowing before reading the API.

It is IPv4 only, deliberately. IPv6 is a different type with different arithmetic (128 bits, no broadcast address, a zone identifier), and folding the two into one type is what makes a library like this hard to read. A caller that needs both wants two types.

The parser is strict, in the same place Go's net/netip is strict: a leading zero in an octet is rejected rather than read as octal. "010.0.0.1" is a different address to inetd, to glibc and to a browser, and silently picking one of the readings is how an allowlist and the thing enforcing it come to disagree. See ParseAddr.

A Prefix keeps the address it was parsed from, so "192.168.1.37/24" stays spelled that way, again as Go does. The block it names is still 192.168.1.0/24, and Prefix.Contains, Prefix.First, Prefix.Last and Prefix.Count all answer for the block. Prefix.Masked is how you get the canonical spelling, Prefix.IsMasked is how you ask whether you already have it.

Live demo: r/moul/x/daily/ipaddrdemo(/r/moul/x/daily/ipaddrdemo/v0).

SpecialBlocks is the IANA IPv4 Special-Purpose Address Registry, which is to say every prefix that is not ordinary public unicast space.

It is ordered by address rather than by specificity, because that is how it reads as a table; Classify does the longest-prefix work instead of relying on the order here.

func MaskOf 

1func MaskOf(bits int) Addr
source

MaskOf returns the netmask for a prefix length: MaskOf(24) is 255.255.255.0. Out-of-range lengths clamp to 0.0.0.0 and 255.255.255.255.

The shift is done in 64 bits on purpose. A 32-bit `^uint32(0) << 32` is undefined in C and, in Go, is a shift count equal to the width, which yields 0 rather than the all-ones a /32 wants; doing it wide and truncating gets both ends of the range right with no special case.

func ParseAddr 

1func ParseAddr(s string) (Addr, bool)
source

ParseAddr reads a dotted-quad IPv4 address and reports whether it was one.

Exactly four decimal octets, each 0 to 255, each written with no leading zero: "0.0.0.1" parses and "00.0.0.1" does not. Nothing else is accepted, which rules out the shorthands the C library takes ("10.1" for 10.0.0.1, "0x0a000001", a trailing dot) and leaves no reading of a string to argue about.

The leading-zero rule is the one that matters for anything security-shaped. "010.0.0.1" is 10.0.0.1 to a browser and 8.0.0.1 to inet_aton, so a parser that accepts it has to pick, and whichever it picks disagrees with something else in the stack.

func Classify 

1func Classify(a Addr) (Block, bool)

Classify returns the most specific entry of SpecialBlocks holding the address, and false when the address is ordinary public unicast space.

Most specific, not first match: 255.255.255.255 is inside 240.0.0.0/4 and is also its own /32 entry, and the /32 is the useful answer.

func ParsePrefix 

1func ParsePrefix(s string) (Prefix, bool)
source

ParsePrefix reads "address/bits" and reports whether it was one.

Both halves are strict: the address goes through ParseAddr, and the bit count is 0 to 32 written with no leading zero, so "10.0.0.0/08" is rejected for the same reason "010.0.0.0/8" is. The address need not be the network address of the block, and is not rewritten if it is not.

func Summarize 

1func Summarize(first, last Addr) []Prefix
source

Summarize returns the shortest list of aligned CIDR blocks that covers exactly the inclusive range first..last, and nothing outside it. The range reversed returns an empty list.

This is the operation a firewall rule, a route table or an allowlist needs and that CIDR notation cannot express directly: an arbitrary range almost never is a prefix. 10.0.0.5 through 10.0.0.20 takes five blocks, and the shape of them (a /32, then wider, then narrowing again) is what greedy alignment always produces.

The greed is in two steps per block, and both are needed. The first takes the widest block that can START at the cursor, which is fixed by how many low bits of the cursor are zero: an address ending in 5 can only begin a /32. The second narrows that block until it also ENDS inside the range. Dropping either step gives blocks that are unaligned or that overshoot.

type Addr

ident

Addr is an IPv4 address, held as the 32-bit number the four octets spell.

The zero value is 0.0.0.0, which is a real address (the unspecified one), so there is no "invalid" Addr: a parse failure is reported by the bool, never by a sentinel value.

func Next

Next returns the following address, and false at 255.255.255.255.

The bool is the point: IPv4 arithmetic wraps silently in 32 bits, so a loop written as `for a := first; a <= last; a++` never terminates when last is the top of the space. Every walk in this package goes through Next or through uint64 arithmetic for that reason.

Prefix is a CIDR block: the address it was written with, and a prefix length in bits.

The address is kept as given rather than masked on construction, so "192.168.1.37/24" renders back as itself. Everything that asks about the block it names, Prefix.Contains, Prefix.First, Prefix.Last, Prefix.Count, masks first.

func Usable

1func (p Prefix) Usable() uint64

Usable returns how many addresses in the block can be assigned to a host: Prefix.Count less the network and broadcast addresses.

A /31 and a /32 are the exceptions and they are not arithmetic. A /31 is a point-to-point link whose two addresses are both hosts (RFC 3021), and a /32 is a single host with nothing to subtract, so both return their full count where the formula would return 0 and -2.
